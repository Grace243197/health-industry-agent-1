## 2. 新增文件与职责

### `tools/report_pdf.py` — Markdown → PDF

- 只用 `fpdf2`（纯 Python，不需要 GTK / 浏览器 / 外部二进制）。
- 中文字体自动探测：`REPORT_FONT` 环境变量 → `simhei.ttf` → `msyh.ttc` → `simsun.ttc` → macOS/Linux 常见路径。
- 支持：`#`~`####` 标题、无序/有序列表、`>` 引用、`|---|` 表格行、分隔线、普通段落。
- 清洗 Markdown 标记与 emoji（多数中文字体没有 emoji 字形，直接去掉，避免出现方块或报错）。
- `wrapmode="CHAR"`：长英文单词和 URL 按字符换行，不会顶出页面。
- 页脚「第 N 页」，页眉固定项目名（避免和正文标题重复）。

### `tools/ask_report.py` — 问答与报告生成

流程：`问题 → 拆关键词 → 本地检索 → 证据去重 → 组织答案 → Markdown → PDF`

- 关键词：按标点/虚词切分，过滤 `什么/怎么/如何/的/是` 等停用词，最多 6 个词，避免把整句拿去子串匹配。
- 证据：调用 `kb_search.search()`，合并多词命中，按 `(source_id, 片段前 60 字)` 去重，默认取前 6 条。
- 答案：有 `DASHSCOPE_API_KEY` 时调 `qwen-plus`（兼容模式），提示词明确"只能用给定证据、每条结论标注 `[Sxxx]`、不足要直说"；无密钥或调用失败 → 原文汇总，并在报告里写明"未调用模型"。
- 报告四节：结论 / 证据清单（表格）/ 逐条溯源（含文件路径）/ 方法与限制。
- 输出：`output/<YYYYMMDD-HHMMSS>_report.md` 与同名 `.pdf`。

### `tools/web_ui.py` — 本地网页窗口

- 只用标准库 `http.server`，不引入 FastAPI/Flask。
- 端点：`GET /`（提问表单 + 最近报告）、`POST /ask`（生成并返回结果页）、`GET /download/<文件>`、`GET /health`。
- 安全：
  - 默认只监听 `127.0.0.1`；
  - `/download/` 只放行 `^\d{8}-\d{6}_report\.(pdf|md)$`，并二次校验最终路径在 `output/` 内（防目录穿越）；
  - 响应带 `X-Content-Type-Options: nosniff`。
- `--no-llm` 可完全不调模型，适合课堂演示与省钱。

## 4. 边界：这只是"最后一公里"，不是 5 Agent 联调

**必须说清楚**：现在的答案来自"本地检索 + 单次模型调用"，**没有**经过调度/采集/知识库/生成/校验五个 Agent 的协作。它解决的是"用户看得到、拿得走"的呈现问题。

下一步接入方式（不改这个外壳）：

```
web_ui / ask_report.answer_question()
        ↓ 未来替换这一行
dispatcher-agent/run_cli.py --task "<问题>"
        ↓
collector → knowledge → generator → verify → 报告
```

也就是说：界面与 PDF 导出已经稳定，等 5 个 Agent 目录补齐后，把 `answer_question()` 里的"检索+模型"换成"调度 Agent"，答案质量就会从"片段汇总"升级为"经双 Agent 互检的结论"，而下载按钮、报告版式完全不用动。
